# 코드 화면(읽기 전용 IDE 보기) 구현 계획

> **실행 방식:** 사용자 지시로 `loop` 워크플로(`.claude/skills/ajh-claude-loop-engineering`)로 구현한다. 작업 단위는 아래 Task 순서, 체크박스(`- [ ]`)로 진행을 표시한다. 커밋은 하지 않는다(결정대장 D-014).
> **개정 1 (2026-11-01):** 3단계 병렬 리뷰(메인·렌더러·설계) 지적 반영 — git 잠금·실행 경로, 경로 검사, 폴더 등록 방식(`code:allow`), 갱신 타이머 규칙, 모나코 수명, 점검 조건.

**목표:** 왼쪽 사무실 영역을 「코드」 화면으로 통째로 덮어, 열린 탭의 작업 폴더(또는 직접 고른 폴더) 전체를 읽기 전용 IDE 처럼 보고, 에이전트가 건드린 파일과 깃 변경 사항을 10초 주기로 확인한다.

**구조:** 메인 프로세스가 허용된 폴더(깃 저장소) 안에서만 `git`·파일 읽기를 수행하고(`src/main/codeRepo.cjs`), 렌더러는 IPC 로 받은 목록·내용을 모나코 편집기(AMD 빌드, 첫 파일을 열 때 지연 로드)로 보여 준다. 사무실은 코드 화면 동안 **그리기만 쉬고 계산은 계속**해서 복귀 때 캐릭터가 제자리에 있다.

**기술:** Electron 45 · 순수 ES 모듈(번들러 없음) · `monaco-editor@0.57.0` `min/vs` AMD 빌드 · `git` CLI · `node:test`

**근거(이번 세션 실측):**
- 모나코 0.57 ESM 빌드는 CSS import 124개 → 번들러 없이 불가. AMD 빌드(`min/vs/loader.js`)는 앱과 같은 CSP·`app://`·sandbox 에서 편집기·구문 색·비교(diff) 동작, 단 CSP 에 `worker-src 'self' blob:` 필요(없으면 워커 생성 차단 → 비교 계산 미완료). 추가 후 콘솔 오류 0, 비교 1.5초, JS 힙 약 20MB. 패키지에 `min-maps` 폴더는 없다(`dev`·`esm`·`min`).
- 갱신 비용: `git status` 39~72ms, `git ls-files` 39~51ms (1회). 폴더 직접 훑기는 큰 프로젝트에서 0.25~2.5초 → 쓰지 않는다.
- `git status --porcelain` 경로는 **저장소 루트 기준**, `git ls-files` 는 **현재 폴더 기준**(하위 폴더에서 실측). 한글 파일명은 `-z` 로 그대로 나온다.
- 사무실 칸을 `display:none` 으로 감추면 확대(>100%) 상태 카메라가 NaN → 덮개(겹치기) 방식만 쓴다. `update` 를 멈추면 복귀 후 캐릭터가 입구부터 다시 걷는다(엔진 이동 0.25초/프레임 상한).
- 리뷰 실측: `path.win32.isAbsolute('C:x') === false` 이고 다른 드라이브면 `path.relative` 가 절대 경로를 돌려준다. `'C:\\Repo2\\x'.startsWith('C:\\Repo') === true`. `fs.realpathSync` 와 `.native` 는 대소문자·8.3 표기가 다르다. `/output/design/` 은 `.gitignore` 대상.

## 자동 결정 (loop 5단계, 리뷰 반영)

- 폴더 등록은 렌더러가 탭을 열 때 `code:allow(cwd)` 로 메인에 알리고 메인이 `checkFolder` 뒤 등록한다(협업 탭은 첫 메시지 전에도 등록되어야 하므로). 렌더러는 이미 `pty:create`·`collab:send` 에 cwd 를 넘기므로 신뢰 경계는 넓어지지 않는다 — 허용 폴더는 실수 방지 장치다. 탭을 닫아도 등록은 유지(세션과 무관한 IDE 개념).
- 「건드린 파일」은 앱 시작부터 모은다(패널 DOM 은 시작 때 만들고 모나코만 지연 로드).
- 모나코 언어는 모델 URI 의 확장자로 모나코가 정한다(별도 언어 표 없음).
- 갱신 시각은 「hh:mm:ss 갱신」(매초 타이머 없음).

## 전역 제약

- 테마·그림 파일(`src/renderer/themes/**`, 이미지)은 수정하지 않는다 (D-002). `view.theme.editor?.editing` 은 읽기만 한다.
- 커밋·푸시·설치 파일 생성은 하지 않는다 (D-014). 패키징 확인은 임시 출력 폴더로만 한다.
- 모나코: `package.json` dependencies 에 `"monaco-editor": "0.57.0"` (정확한 버전 고정 — AMD 빌드는 지원 중단 예고). 불러오기 경로 `../../node_modules/monaco-editor/min/vs` (index.html 기준). `loader.js` 는 **index.html 에 정적으로 넣지 않고** 처음 파일을 열 때 주입한다 — xterm UMD 가 전역 `define.amd` 를 보고 AMD 로 등록되는 것을 막기 위함.
- CSP 변경은 `worker-src 'self' blob:` 추가 하나뿐.
- 편집기: 일반 편집기 1개·비교 편집기 1개를 처음에 만들어 재사용. 옵션 `readOnly: true`, `domReadOnly: true`, `theme: 'vs-dark'`, `automaticLayout: true`. JS·TS 언어 서비스 끔: `monaco.typescript.typescriptDefaults`·`javascriptDefaults` 각각 `setDiagnosticsOptions({ noSemanticValidation: true, noSyntaxValidation: true })` + `setModeConfiguration({})` 의 모든 항목 false(completionItems·hovers·documentSymbols·definitions·references·documentHighlights·rename·diagnostics·documentRangeFormattingEdits·signatureHelp·onTypeFormattingEdits·codeActions·inlayHints) — 단독 모델의 가짜 빨간 줄과 TS 워커 상주 방지. 모델을 버릴 때는 `diffEditor.setModel(null)` 먼저, 그다음 `dispose()`.
- git 실행 (`codeRepo.cjs` 의 내부 `git(root, args, { buffer })`):
  - 실행 파일은 처음 한 번 찾아 기억: `claudeCli.run('where', ['git'])`(앱 프로세스 cwd 에서 — 저장소 폴더에 둔 `git.exe` 를 잡지 않게)의 첫 `.exe` 줄, 없으면 `%ProgramFiles%\Git\cmd\git.exe`, 둘 다 없으면 `no-git`.
  - 공통 인자 `['--no-optional-locks', '-c', 'core.quotepath=false', '-c', 'core.fsmonitor=false', ...args]` — 에이전트의 `git add`·`commit` 과 `index.lock` 충돌 방지, 저장소 설정의 fsmonitor 명령 실행 방지.
  - `execFile(gitPath, args, { cwd: root, env, windowsHide: true, timeout: 10000, maxBuffer: 64 * 1024 * 1024, encoding: 'buffer' })`, `env` = `cleanEnv()` 에서 `GIT_DIR`·`GIT_WORK_TREE`·`GIT_INDEX_FILE` 제거 + `LC_ALL: 'C'`.
  - 결과 구분: 실행 파일 없음(ENOENT) → `no-git`, stderr 에 `dubious ownership` → `unsafe`, 그 밖의 실패 → `not-repo`(rev-parse) 또는 오류 throw.
- 상한: 트리 20000개(추적 파일 먼저, 남은 자리에 미추적 파일, 넘으면 `truncated: true`), 파일 읽기 2MB(stat 으로 먼저 확인, 넘으면 `large`), 바이너리 판정 = 앞 8000바이트에 NUL, 「건드린 파일」 폴더별 50개.
- 허용 폴더·경로: 모든 `code:*` 는 등록된 폴더(`code:allow`·`code:pick`)이면서 깃 저장소인 경우만, 상대 경로는 아래 `resolveInside` 를 통과한 것만.
- 주석·문구는 한국어, 주변 코드의 밀도·관용구를 따른다.

## 리뷰 중점 (테스트로 고정할 실패 양상)

1. 한글·공백이 든 파일 경로 → 트리·상태·읽기가 모두 같은 상대 경로로 맞아야 한다 (Task 1 테스트).
2. 탭 작업 폴더가 깃 저장소의 **하위 폴더** → 상태 경로에서 접두어를 떼고, 폴더 밖 변경은 빼야 한다 (Task 1 테스트).
3. 에이전트가 커밋하는 순간과 10초 조회가 겹침 → 조회가 `.git/index` 를 쓰지 않아야 한다 (Task 1 테스트).
4. 열어 둔 파일이 지워지거나 이름이 바뀜 → 오류 없이 「파일이 없습니다」 표시, 트리는 다음 갱신에서 정리 (Task 1 `missing` 테스트 + Task 5 화면 처리).
5. 코드 화면을 보는 동안 에이전트 활동 → 사무실로 돌아오면 캐릭터가 이미 걸어가 있어야 한다 (Task 4 점검 스크립트).

  `rel` 이 문자열이 아니거나 빈 값 · `:` 포함(드라이브 상대 `C:x`, 대체 데이터 스트림 `a.js:stream`) · `path.isAbsolute` · `/`·`\` 로 나눈 조각 중 `..` 또는 대소문자 무시 `.git` · `out = path.relative(root, abs)` 가 `''` 이거나 `..` 로 시작하거나 절대 경로 · 대상이 존재하면 `fs.realpathSync.native(abs)` 가 `fs.realpathSync.native(root)` 와 같거나 `+ path.sep` 로 시작하지 않음(win32 는 둘 다 소문자로 비교).
- `toGitPath(rel: string): string` — `\` → `/`.
- `createCodeRoots(): { add(dir): void, has(dir): boolean, list(): string[] }` — 키 = `path.resolve(dir)` 끝 구분자 제거, win32 는 소문자. `list()` 는 처음 넣은 표기 그대로.
- `repoInfo(root): Promise<{ git: true, prefix: string } | { git: false, reason: 'not-repo' | 'no-git' | 'unsafe' }>` — `rev-parse --show-prefix`, `prefix` 는 `'sub/'` 형식(루트면 `''`).
- `listFiles(root): Promise<{ files: string[], truncated: boolean }>` — `ls-files -c -z` 로 추적 파일, 남은 자리만큼 `ls-files -o --exclude-standard -z` 로 미추적 파일, 합쳐 정렬.
- `statusOf(root, prefix): Promise<Array<{ path: string, code: string }>>` — `status --porcelain=v1 -z -uall -- .`; 항목 앞 2글자가 `code`, `R`·`C` 는 다음 토큰(원래 경로) 건너뜀, `prefix` 로 시작하지 않는 항목 제외 후 접두어 제거.
- `readText(root, rel, maxBytes = 2 * 1024 * 1024): Promise<{ kind: 'text', text: string, mtimeMs: number } | { kind: 'binary' } | { kind: 'large', size: number } | { kind: 'dir' } | { kind: 'missing' }>` — `stat` 먼저(없음 → `missing`, 폴더·서브모듈 → `dir`, 크기 초과 → `large`), 그다음 읽기.
- `statMtime(root, rel): Promise<number | null>`
- `headText(root, rel, maxBytes = 2 * 1024 * 1024): Promise<string | null>` — `show HEAD:./<toGitPath(rel)>`(buffer), 실패·바이너리·초과면 `null`.
- `createCodeService({ roots }): { tree(root), poll(root, rel), read(root, rel), base(root, rel) }` — 모든 메서드가 먼저 `roots.has(root)`(아니면 `Error('허용되지 않는 폴더입니다')`), 이어서 root 별로 기억한 `repoInfo` 가 git 이 아니면: `tree` 는 그 결과 `{ git: false, reason }` 반환, 나머지는 `Error('깃 저장소가 아닙니다')`. `rel` 은 `resolveInside` 로 검사.
  - `tree(root)` → `{ git: true, ...await listFiles(root) }`; `poll(root, rel | null)` → `{ changes: await statusOf(root, prefix), mtimeMs: rel ? await statMtime(root, rel) : null }`; `read` → `readText`; `base` → `{ text: await headText(root, rel) }`.
- `registerCodeIpc(handleMain, { roots, service, pickFolder, checkFolder }): void` — 채널: `code:allow`(`{ cwd }` → `checkFolder(cwd)` 후 `roots.add(cwd)`, 반환 `true`), `code:pick`(→ `await pickFolder()` 가 경로면 `roots.add` 후 그 경로, 취소면 `null`), `code:tree`·`code:poll`·`code:read`·`code:base`(`{ root, rel }` → 서비스). 인자가 객체가 아니거나 `root` 가 문자열이 아니면 `Error('잘못된 요청입니다')`.

## 사용자 화면 확인 체크리스트 (D-003, 구현 후 사용자에게 전달)
