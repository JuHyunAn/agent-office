# Agent Office

Claude Code 의 메인 세션과 하위 에이전트를 **사무실에서 일하는 캐릭터**로 보여 주는 데스크톱 앱.
왼쪽은 사무실(항상 표시), 오른쪽은 **공식 Claude Code**·**Codex**·**Grok Build**·**Muse Code**·**Gemini**(Antigravity CLI · `agy`) 탭과 Claude·Codex·Grok·Muse·Gemini 가 함께 이야기하는 **협업 대화** 탭을 여러 개 띄운다.

## 실행

```bash
npm install
npm start        # IDE 터미널에서도 동작 (ELECTRON_RUN_AS_NODE 를 지우고 실행)
npm test         # 엔진·hook 처리 단위 테스트
npm run test:renderer # 합성 이벤트로 Electron 화면·픽셀 액션 검증 및 캡처
npm run dist     # Windows 설치 파일 생성 → dist/
```

필요: Node 20+, 그리고 AI CLI 하나 이상 — 지원 AI 는 Claude Code(메인 지원)·Codex·Grok Build·Muse Code·Gemini(Antigravity CLI) 다. CLI 는 설치 파일에 넣지 않는다 — 진입 화면의 「설치」 버튼(아래)으로 깔거나 직접 설치한다. 로그인은 각 공식 CLI 가 한다.
Codex 탭·협업 대화는 Codex 가 연결(로그인)됐을 때만 고를 수 있다 — PATH 의 `codex`(`npm install -g @openai/codex`) 또는 Codex 데스크톱 앱에 포함된 CLI(`%LOCALAPPDATA%\OpenAI\Codex\bin\…\codex.exe`)를 자동으로 찾는다. 로그인은 Codex 가 한다.
**진입 화면**은 왼쪽 AI 목록(Claude Code · Codex · Grok Build · Muse Code · Gemini — 점으로 연결됨/로그인 필요/오류/미설치를 구분하고 계정 요약을 보임)과 오른쪽 고른 AI 의 상세(설치 · 설치 안내 · 로그인 · 계정)로 나뉜다. 맨 위에 「연결 n/N」과 「입장하기」가 있으며, **AI 가 하나 이상 연결(로그인)되면 입장할 수 있다** (Claude 를 메인으로 지원하고, 다른 AI 는 연결하면 함께 쓸 수 있다). 목록은 방향키로도 고를 수 있다.
상단의 「연결 n/N」 칸을 누르면 같은 목록이 대화상자로 뜬다 (입장 뒤 로그인은 거기서 「{AI} 로그인」 탭을 연다). 판정은 `claude auth status` / `codex login status` 이며, Codex 이메일·플랜은 app-server `account/read` 로 덧붙인다.
**설치**(Windows): 미설치 AI 를 고르면 「{AI} 설치」 버튼이 있다. 누르면 공식 PowerShell 설치 명령(`irm … | iex`, 명령은 앱 레지스트리 `src/shared/agents.js` 의 것만 실행)을 앱 안 터미널에서 실행하고, 끝나면 자동으로 다시 확인한다. 설치 파일에는 CLI 를 넣지 않으며, 이 PowerShell 프로세스에만 실행 정책을 우회하고 사용자 설정은 바꾸지 않는다. Windows 가 아니면 버튼 없이 명령과 「설치 안내」 링크만 보인다. 입장 뒤에는 상단 「연결 n/N」 대화상자에서도 같은 버튼으로 「{AI} 설치」 탭을 연다.
**Grok Build** 는 협업 대화에 참여하고 사무실 캐릭터도 보인다 — Grok 은 세션 단위로 hook 을 넣는 공식 경로가 없어(1.0.70 실측) 공식 위치 `~/.grok/hooks/agent-office.json` 에 이 앱 전용 HTTP hook 파일 하나를 **자동으로** 둔다. Grok 탭이나 Grok 협업을 처음 만들 때 파일이 없으면 만들고, 앱을 다시 켜 포트·토큰이 바뀌면 앱이 만든 파일만 새 값으로 고쳐 쓴다(별도 켜기·끄기·확인 창 없음). 같은 이름의 다른 파일이 이미 있으면 건드리지 않고, 다른 Grok 설정 파일도 고치지 않는다. 앱 밖에서 실행한 Grok 세션도 사무실에 보이고, 앱이 꺼져 있으면 이벤트는 버려져 Grok 작업에는 영향이 없다. 이미 실행 중인 Grok 은 다시 시작해야 반영된다. Grok 에는 권한 요청 hook 이 없어 펫 권한 카드가 없고, 협업 중 답변 가로채기도 지원하지 않는다(진행자가 턴이 끝난 뒤 전달). 로그인은 `grok login` 이다.
**Muse Code** 는 협업 대화에 참여하고 사무실 캐릭터도 보인다 — 사무실 표시는 설정 파일을 고치지 않고 **세션 단위 hook**(실행할 때마다 `-c hooks.<이벤트>=…` 인자)으로 넣으며, 앱 탭과 협업 방마다 주소의 `tab` 으로 어느 탭인지 알린다. hook 명령은 따옴표·공백 든 인자를 쓰지 않는 `curl.exe` 한 줄이고(Muse 가 명령의 큰따옴표를 지운다 — 1.4.14 실측), 비동기라 Muse 작업을 막지 않는다. `curl.exe` 는 `%SystemRoot%\System32\curl.exe` 절대 경로로 부른다 — Muse 는 hook 을 `cmd /C` 로 돌리고 cmd 는 현재 폴더를 먼저 찾으므로, 이름만 쓰면 작업 폴더에 심어 둔 `curl.exe` 가 실행될 수 있다(경로에 공백·특수문자가 있으면 hook 을 넣지 않고 탭만 연다). `--url-query` 때문에 curl 7.87 이상이 필요하다(Windows 기본 curl 8.x — 실측 8.19). 앱은 런처 shim(`muse.cmd`)이 아니라 설치 폴더의 `muse-bin-*.exe` 를 직접 실행한다(shim 은 JSON 인자를 깨뜨린다. 실행 파일을 못 찾아 shim 만 쓸 때는 탭은 열리지만 사무실 표시는 없고 협업은 「Muse 를 다시 설치하세요」 오류). 버전 확인만 shim 으로 불러 런처의 자동 업데이트가 돌게 한다. Muse 탭은 **사무실 캐릭터와 「확인 필요」(작업 완료)까지** 보이고, 펫 권한 카드는 없으며(관찰용 비동기 hook 이라 승인을 전달할 수 없다), 탭 안에서 `/new` 로 만든 뒤의 세션은 탭에 붙지 않는다(Grok 과 같은 한계). 대화형 화면에서의 hook 발화는 `exec`·`serve` 로만 실측했다. 도구 호출 기록의 모양도 실제 모델 응답으로는 확인하지 못했다(로그인 없이 쓰는 시험 제공자 `--provider echo` 로만 실측 — 비용 0).
**Muse 계정**: 로그인(`muse login`, 브라우저에서 코드 승인)만으로는 쓸 수 없다. 결제 수단을 등록한 Meta 계정(종량제) 또는 구독이 없으면 로그인 직후 CLI 가 자격 증명을 지우고 「requires a payment method」 안내를 낸다(실측). 공식 문서상 무료 플랜은 없다. 진입 화면의 Muse 상세(로그인 필요·오류 상태)에 이 안내와 「Meta 계정 설정 열기」 버튼이 있다.
**Gemini(Antigravity CLI · `agy`)** 는 설치·로그인 확인·새 탭(공식 화면을 그대로 띄움)과 **사무실 캐릭터**까지 되고 협업 대화에도 참여한다 (사용량 패널에는 사용량 조회 명령이 없어 협업 대화의 토큰 합계만 보인다). `--settings` 가 hooks 를 거부해("unknown setting") 세션 단위로 넣을 수 없으므로, 공용 `~/.gemini/config/hooks.json` 에 이 앱 이름(`agent-office`)의 항목 하나를 **자동으로** 넣는다. Gemini 탭을 처음 만들 때 항목이 없거나 포트·토큰이 다르면 맞추고, 앱을 다시 켜 값이 바뀌었으면 이미 있는 항목만 고쳐 쓴다. 파일이 이미 있으면 다른 키는 그대로 두고 우리 항목을 처음 넣을 때 한 번 `hooks.json.agent-office-backup-<시각>` 으로 백업하고(항목을 지웠다가 다시 쓸 때는 새 백업을 만들지 않는다) 임시 파일에 쓴 뒤 바꿔치기해 저장한다. 파일이 깨진 JSON 이거나 객체가 아니거나 `agent-office` 키가 다른 용도(객체가 아닌 값)면 건드리지 않고 Gemini 연결 상세에 안내를 띄운다. agy 쪽에서 항목의 `enabled` 를 꺼 두었으면 그 값을 다시 켜지 않는다. 앱 안에는 이 항목을 지우는 버튼이 없다 — 더 이상 쓰지 않으려면 `hooks.json` 에서 `"agent-office"` 키를 직접 지우면 된다(백업 파일은 그대로 남는다). hook 은 `cmd` 로 실행되는 `curl.exe`(`%SystemRoot%\System32\curl.exe` 절대 경로) 한 줄이고(끝은 `>nul 2>nul & exit /b 0` — Antigravity CLI 는 hook 이 실패하거나 `{}` 를 돌려주면 모든 도구를 거부하므로 출력 없이 항상 성공으로 끝낸다, 1.4.12 실측), 명령 안의 `%AGENT_OFFICE_TAB%` 가 앱 탭의 환경변수로 치환되어 어느 탭인지 알린다 (앱 밖에서 실행한 agy 세션은 치환되지 않아 탭 없이 외부 세션으로 보인다). 이벤트는 SessionStart·PreToolUse·PreInvocation(첫 호출을 프롬프트 제출로)·Stop 이며, 형식은 도구 이벤트(PreToolUse)만 `matcher`+`hooks` 로 감싸고 그 밖 이벤트는 hook 객체를 바로 나열한다(감싸면 agy 가 파일 전체를 거부한다 — 1.4.12 실측). 앱이 꺼져 있으면 이벤트는 버려져 agy 작업에는 영향이 없고, 이미 실행 중인 agy 는 다시 시작해야 반영된다. 로그인은 `agy` 첫 실행 브라우저 로그인이며, 로그인 화면이 터미널 UI 라 마친 뒤 터미널을 닫거나 「다시 확인」을 누른다 (Grok·Muse 도 로그인 터미널이 저절로 끝나지 않으면 닫고 「다시 확인」).
로그인은 공식 `claude auth login` / `codex login`(브라우저)이며, 진입 화면 터미널 또는 입장 뒤 「{AI} 로그인」 탭에서 한다. Claude Code 가 없으면 「다른 세션 보기」는 숨겨지고 이어받기는 막힌다. 알려진 임시 상태: Claude 없이 입장하면 코드 분석(Claude 필요)은 쓸 수 없다.
`AGENT_OFFICE_SMOKE=collab` 로 실행하면 실제 화면에서 협업 대화(Claude·Codex 실제 호출, 사용량 소량)와 Codex 탭을 한 번 점검한다. `AGENT_OFFICE_USER_DATA` 로 점검용 데이터 폴더를 따로 지정할 수 있다.

## 설치 파일 (다른 PC)

`npm run dist` 가 `dist/` 에 두 가지를 만든다 (Windows x64).

- `AgentOffice-Setup-<버전>.exe` — 설치형. 관리자 권한 없이 사용자 폴더에 설치하고 시작 메뉴·바탕화면 바로가기와 제거 기능을 만든다.
- `AgentOffice-Portable-<버전>.exe` — 무설치. 실행할 때마다 임시 폴더에 풀어서 실행하므로 시작이 느리다.

받는 PC에는 **Claude Code CLI**(메인 지원)가 있으면 된다 (Node·npm 은 앱에 포함. Codex 만 있어도 입장은 된다). 처음 실행해 로그인하지 않았으면 앱 안에서 공식 로그인을 띄운다.
코드 서명이 없어 처음 실행할 때 Windows SmartScreen 경고가 뜬다 → 「추가 정보」 → 「실행」.
사용자 데이터(커스터마이징 사무실·테마 선택·최근 폴더)는 PC·Windows 사용자별 `%APPDATA%\agent-office` 에 저장되며 개발 실행(`npm start`)과 같은 위치를 쓴다. 다른 PC 로 옮겨지지 않는다.
터미널 모듈(node-pty)은 미리 빌드된 Windows 바이너리를 쓰므로 받는 PC 에 빌드 도구가 필요 없다.

## 동작 방식

```
Claude Code (탭·VS Code 등) ──HTTP hook──▶ 앱 내부 서버 127.0.0.1:47821 ──▶ 사무실 엔진 ──▶ 테마가 그림
       ▲
       └── 오른쪽 탭: node-pty 로 공식 `claude` 실행 (--settings 로 hook 주입, --session-id 로 탭과 연결)
```

| 화면 | 연결 이벤트 |
|---|---|
| 입구 → 방으로 출근 | `SubagentStart` (종류별 방: 분석·기획·개발·검토) |
| 말풍선 「⌨ 수정 중: …」 | `PreToolUse` (하위 에이전트 것은 `agent_id` 로 구분) |
| 팀장실로 가서 보고 → 휴게실 | `SubagentStop` |
| 앞쪽 하위 에이전트가 휴게실로 | 메인 `Stop`·새 요청 때 끝 신호(`SubagentStop`)를 못 받은 앞쪽 하위 에이전트 (백그라운드는 계속 일함, 답하는 중 보낸 메시지에는 10초 안에 신호가 있던 하위를 그대로 둠). 하위 에이전트는 5분 무신호여도 휴게실로 (그 뒤 1분이면 퇴근) |
| 「📨 결과 공유 중...」 다른 자리로 이동 | 끝난 직후 30초 안에 다음 에이전트 시작 (**추정** — 가끔 틀릴 수 있음) · `SendMessage` 는 정확 |
| 빨간 「❓」 말풍선 | `PermissionRequest`·`Notification` |
| 팀장 「✅ 답변 완료」 | `Stop` |
| 「👋 퇴근합니다」 | 하위 에이전트는 일을 마치고(휴게실) **1분**, 팀장은 답변을 마치고 **3분**, 세션이 끝나면(`SessionEnd`·탭 닫기) 휴게실에 모였다가 **1분** 뒤 함께. 끝 신호가 끊겨 휴게실로 간 경우(하위 5분·팀장 20분 무신호)에도 휴게실에 간 때부터 각각 1분·3분. 사용자 확인을 기다리는 동안은 남는다. 퇴근한 뒤 다시 일하면 같은 이름·외형으로 다시 출근한다 |
| 협업 대화에서 오류·중단된 AI 는 바로 작업 끝 | 협업 중 AI 가 오류나 중단으로 끝나면 `Stop` 이 오지 않으므로, 대화창 상태(오류·중단)를 보고 사무실에서도 바로 「작업 끝」(대기)으로 돌린다. 그 뒤 퇴근 규칙은 위와 같다 |
| 말풍선 배경이 천천히 깜빡임 · 탭 점 빨강 (「확인 필요」) | 보고 있지 않은 탭의 `Stop`·`PermissionRequest`·답이 필요한 `Notification`·`AskUserQuestion`, 협업 대화의 질문·완료·오류. 그 탭을 누르거나 터미널·대화창을 클릭하면 꺼진다. 다른 곳의 세션은 답이 필요한 것만 켜지고 진행되거나 20분 뒤 꺼진다 |

- **창 닫기 = 숨기기**: 창의 X 는 앱을 끄지 않고 숨긴다 (Claude 세션·사무실 계속 동작). 작업 표시줄 「숨겨진 아이콘」의 Agent Office 아이콘을 클릭하면 다시 열리고, 실제 종료는 그 아이콘 메뉴의 「종료」로 한다.
- **바탕화면 펫**: 화면 오른쪽 아래에 작은 펫이 떠서 작업 중·확인 필요 상태를 보여 준다. 상시 표시 모드에서는 지금 쓰는 AI(탭을 연 AI, 협업 탭이면 참여 AI 전부)만 가로 한 줄로 나온다 — 앱을 켠 직후 탭이 없으면 펫도 없고, 여러 AI 를 함께 쓰면 펫이 그만큼 늘어난다. 확인이 필요한 알림이 온 AI(앱 밖 세션 포함)는 탭이 없어도 나오고, 탭은 닫을 때까지(프로세스가 끝나도) 쓰는 중으로 본다. 펫 그림이 없는 AI 는 사무실 캐릭터를 크게 그려 대신 쓴다. 끌어서 옮기면 위치를 기억하고, 펫이나 말풍선을 클릭하면 해당 탭이 열린다. 상단 「펫」 또는 트레이 메뉴에서 상시 표시·알림만 표시·끄기를 고른다 (트레이 메뉴에 「펫 위치 초기화」도 있음). 펫 그림은 Codex 펫 형식(`pet.json` + 1536x1872(9줄) 또는 1536x2288(11줄, Codex 새 형식 — 커서를 바라봄) 시트)이다.
  - **펫 그림**: 「펫 그림」 화면에서 AI 별로 기본 · 아이콘만 · 기본 제공 · 가져온 펫 중에서 고른다. codex-pets.net 에서 받은 zip 이나 폴더를 가져올 수 있다 — 선택 창에서 여러 개를 한 번에 고르면 차례로 가져오고, 실패한 것은 이유와 함께 알려 준다(한 번에 50개까지) (1536x1872(9줄) 또는 1536x2288(11줄, Codex 새 형식 — 커서를 바라봄) png·webp, 최상위 폴더는 한 겹까지, zip 32MB·항목 64개 이하). 같은 이름이 이미 있으면 `-2` 를 붙여 따로 설치하고, 앱 데이터 폴더의 `pets/` 에 복사해 둔다. 가져온 펫은 삭제할 수 있으며, 지운 펫을 고른 종류는 기본으로 돌아간다. 기본 펫 그림의 출처는 결정대장 D-029 에 있다.
  - **권한 허용·거부**: 앱 탭의 Claude·Codex 가 권한을 물으면 펫 위에 카드(도구·명령 미리보기)가 뜨고 [허용] [거부] 로 바로 답할 수 있다 (Claude 는 터미널 승인 화면과 둘 중 먼저 답한 쪽이 적용). 명령(Bash·PowerShell·Read·WebFetch·WebSearch·LS 의 실행 필드)이 160자·4줄(줄바꿈 3개)을 넘거나 카드에 보이지 않는 입력이 함께 있거나 (Glob·Grep 포함) 그 밖의 도구(파일 쓰기·MCP·질문 등)이거나 앱 밖 세션이면 버튼 없이 안내만 한다 (카드에는 승인 대상 전체가 보이는 경우에만 버튼이 뜬다). 카드가 사라지거나 펫이 꺼지거나 590초가 지나면 앱이 응답을 풀어 원래 터미널 승인으로 넘긴다. Codex 는 카드가 떠 있는 동안 터미널 승인 화면이 없으므로, 그 탭을 보고 있으면 2~3초 안에 터미널 승인으로 넘긴다.
  - **사용량 패널**: 펫 위 패널(∨/∧ 로 접기, 접힘 상태 기억)에 Claude 세션(5시간)·주간·모델별 주간 사용률과 재설정 시각, Codex 한도, Grok 세션 토큰·비용, Muse 구독 한도, Gemini 협업 대화 토큰, 지금 보는 탭의 요청 수·컨텍스트 %를 보여 준다 (펫이 보이지 않는 AI 와 사용량 정보가 없는 AI 의 칸은 숨긴다). 모델 요청이 드는 출처는 쓰지 않으며, 펫을 꺼도 수집은 계속된다. 한도 %가 아닌 수치(토큰·비용)는 막대 없이 글로만 보인다.
    - **출처**: ① 앱 Claude 탭의 상태 표시줄 중계 — Claude 가 응답마다 넘기는 사용률·컨텍스트를 받는다. 사용자 상태 표시줄(HUD)은 중계가 대신 실행해 그대로 보이며, `node` 가 PATH 에 없으면 중계를 쓰지 않는다. ② 숨긴 claude 로 `/usage` 화면 읽기 — 모델 요청 없음, MCP·자동 업데이트·입력 기록(history) 끔. 앱 시작 2분 뒤 한 번, 이후 1시간마다(그 사이 Claude 를 썼을 때만), ⟳ 수동 갱신은 5분 간격. 연달아 3번 실패하면 자동 갱신을 멈춘다. ③ Codex — 탭의 롤아웃(`token_count`)에서 읽고, 1시간 넘게 값이 없으면 `codex app-server` 로 한도만 조회. ④ Grok — 앱 탭·협업 방에서 응답이 끝날 때마다(⟳ 와 별개로) `grok usage <세션>` 으로 그 세션의 토큰·비용·호출 수를 읽는다(로컬 기록, 모델 요청 없음. 비용 단위 10^10 ticks = 1 USD 는 미확인 가정). ⑤ Muse — `muse usage --json` 으로 구독 한도를 읽는다(자동 갱신은 Muse 를 쓴 뒤에만, ⟳ 는 항상. 미로그인이면 안내만, 출력 형식은 로그인 계정에서 확인하지 못해 방어적으로 읽음). ⑥ Gemini(Antigravity CLI) — 조회 명령이 없어 협업 대화 턴의 토큰을 앱 실행 동안 누적.
    - **남는 흔적**: `~/.claude.json` 에 앱 전용 폴더(`usage-probe`)의 신뢰 기록·통계, Claude 가 스스로 순환하는 `~/.claude/backups`, `~/.claude/projects/` 아래 빈 폴더(읽기마다 세션 기록과 빈 폴더는 지우지만 못 지운 것이 남을 수 있음). 그 밖의 사용자 설정 파일은 고치지 않는다.
    - **한계**: 앱 탭에서 쓸 HUD 는 Claude 와 같은 우선순위(프로젝트 `.claude/settings.local.json` → 프로젝트 `.claude/settings.json` → 사용자 `~/.claude/settings.json`)에서 처음 찾은 command 형식이며, Git Bash(없으면 PowerShell)로 실행한다. Claude 가 중계를 강제 종료하면 HUD 자식 프로세스가 잠시 남을 수 있다. 모델별 사용률은 `/usage` 읽기에서만 얻는다.
- **앱 탭의 세션**: 자동으로 사무실에 나타난다 (사용자 설정 변경 없음).
- **VS Code 등 다른 곳의 세션**: 상단 「다른 세션 보기」를 켜면 `~/.claude/settings.json` 에 hook 이 추가된다 (백업 후 수정, 끄면 이 앱 것만 제거). 앱이 꺼져 있어도 Claude 작업은 영향 없음 (실측).
- **이어받기(복제)**: 다른 곳 세션을 `--resume <id> --fork-session` 으로 복제해 새 탭에서 이어 간다. 원래 세션은 그대로.
- **새 탭 종류**: 「＋」 새 탭 창은 왼쪽 AI 목록(연결된 것만 활성)·오른쪽 프로젝트 목록으로 나뉜다. 왼쪽에서 AI 또는 협업 대화를 고르고 (마지막 선택을 기억) 오른쪽에서 작업 폴더를 고른다. 협업 대화를 고르면 **참여할 AI 를 체크**한다 (연결된 AI 만, 2개 이상). 참여 AI 가 여럿이면 차례대로 돌아가며 답하고, 제안한 AI 를 뺀 모두가 이어서 `[완료]` 해야 끝난다. 지금은 협업 실행기가 있는 Claude·Codex·Grok·Muse·Gemini 만 고를 수 있고, 연결된 둘 이상이 있어야 협업이 열린다. Grok 은 턴마다 `grok --prompt-file … --output-format streaming-json --always-approve`(승인 없이 실행) 로 실행하고 `-r` 로 같은 세션을 이어 간다. Muse 는 턴마다 `muse exec --json --prompt-file … --session-id <방마다 같은 UUID> --approval-mode never`(승인 없이 도구 실행 — Codex·Grok 협업과 같은 수준) 로 실행해 같은 세션 ID 로 대화를 이어 가고(첫 턴에만 협업 규칙을 앞에 붙임), 모델은 자동·Muse Spark 1.3·Muse Spark 1.2·Muse Wonder 1.0(미리보기, 한국 미제공) 고정 선택지다(모델 목록 조회는 없다 — 협업 모델 목록 결과에 muse 키가 없고 화면이 고정 선택지를 쓴다). Gemini 는 턴마다 `agy -p <프롬프트> --output-format stream-json --dangerously-skip-permissions`(승인 없이 실행) 로 실행하고 `--conversation <agy 가 정한 대화 ID>` 로 같은 대화를 이어 가며(첫 턴에만 협업 규칙을 앞에 붙임), 모델 목록은 `agy models` 에서 읽고 Gemini 모델만 보인다 (단계는 「Gemini 3.8 Flash (High)」 처럼 모델 이름에 들어 있어 따로 고르지 않는다). 로그인 전이면 방을 만들 때 안내 오류를 낸다.
- **Codex 탭**: 공식 `codex` 화면을 그대로 띄운다 (기본 승인 모드, `/permissions` 로 변경). 사무실 표시용 hook 은 실행 인자 `-c hooks.…` 로만 넣고 `~/.codex` 설정은 바꾸지 않는다. Codex hook 은 명령 실행만 지원하므로 Windows 기본 `curl.exe` 로 앱 서버에 보낸다. 탭마다 주소가 달라 Codex 의 hook 신뢰 기록과 맞지 않으므로 `--dangerously-bypass-hook-trust` 로 실행한다 (이 실행에 한해 저장소의 다른 hook 도 검토 없이 실행될 수 있음).
- **협업 대화**: 나 · Claude · Codex 가 한 대화창에서 이야기한다.
  - Claude 는 `claude -p --input-format/--output-format stream-json`(글자 단위 실시간), Codex 는 턴마다 `codex exec --json` → `exec resume` 으로 같은 세션을 이어 간다 (문단·명령 단위 실시간).
  - **Bypass 모드**로 실행한다 (Claude `--dangerously-skip-permissions`, Codex `--dangerously-bypass-approvals-and-sandbox`) — 확인 없이 파일 수정·명령 실행.
  - 상단에서 **구현 담당**(Claude / Codex / 구현 전에 물어보기)과 각자의 **모델·추론 단계**를 고른다. 「자동」은 사용자의 최근 요청으로 고른다: 어려운 추론(설계·원인·분석·검토 등) → Fable / GPT-6 Astra + Extra High, 설계가 끝난 단순 작업(주석·오타·문법·설계대로 구현) → Sonnet / GPT-6.1 Sol + High, 그 외 → Opus / GPT-6.1 Sol + High. 각 AI 에게는 하위 에이전트도 같은 기준으로 쓰라고 지시한다.
  - 모델·추론 단계 선택지는 각 CLI 에서 직접 받아 온다 (Claude: 헤드리스 시작 응답의 모델 목록, Codex: `codex debug models`). 앱 실행 중 한 번 조회하고, 고른 모델이 지원하는 단계만 보여 준다. 받아 오지 못하면 기본 선택지(Opus·Fable·Sonnet / GPT-6.1 Sol·GPT-6 Astra, High·Extra High)를 쓴다.
  - 횟수 제한 없이 Claude ↔ Codex 가 번갈아 이어 간다. 입력창 버튼 하나로 보내기와 중단을 겸한다 — 글을 쓰면 보내기(Enter), 답변 중에 입력이 비어 있으면 버튼이 중단으로 바뀐다. Esc 는 입력 내용과 관계없이 답변 중이면 중단한다. Claude 가 답하는 중에 보낸 메시지는 지금 답변에 바로 반영되고(받은 순간 말풍선이 나뉘어 내 메시지 아래로 이어 답함), Codex 가 답하는 중에 보낸 메시지도 지금 답변에 반영된다 — 하던 작업(명령 등)이 끝난 지점에서 지금 실행을 멈추고 같은 세션으로 그 메시지를 받아 이어 답한다(그런 지점이 없으면 답이 끝난 직후 이어 답함). 반영될 때까지 내 메시지에 「반영 대기 중」이 표시된다. 상대에게 보낸 메시지는 다음 차례에 함께 전달된다. 버튼 아이콘은 Heroicons(Copyright (c) Tailwind Labs, Inc., MIT License — https://github.com/tailwindlabs/heroicons/blob/master/LICENSE). `@claude`·`@codex` 로 받는 사람을 지정하고, 「자동 이어가기」를 끄면 지정한 상대만 답한다.
  - 중요한 선택은 AI 가 `[질문]` 줄로 묻고 사용자가 답할 때까지 멈춘다. 자동 이어가기는 두 AI 가 서로 토론해 둘 다 만족하는 최종 답변을 낸다 — 한쪽의 `[완료]` 는 최종안 제안이고 상대도 이어서 `[완료]` 하면 멈추며 그 최종안에 「최종 답변」 표시가 붙는다. 코드 작업은 계획을 합의한 뒤 승인 버튼으로 사용자 승인을 받고 구현하며, 구현 담당 구현·검증 → 상대 검토 → 결함 수정 고리를 최대 3회 돈다. 두 AI 모두 「가정 드러내기·가장 단순한 방법·필요한 곳만 수정·완료 기준으로 검증」 원칙을 따른다 (협업 대화에만 적용, 공식 탭은 그대로).
  - 「모두에게」 보내면 두 AI 가 한 번씩 답한 뒤 `[완료]`·`[질문]` 을 따른다 (답변 중 끼어든 「모두에게」 메시지도 둘 다 답함). 이 규칙은 새 협업 탭부터 적용된다 (Codex 는 첫 턴에 규칙을 받는다).
  - AI 가 `[질문]` 아래 `[선택]` 줄로 선택지를 주면 버튼으로 고를 수 있고 (답은 「선택: 이름」으로 질문한 AI 에게 간다), 입력창으로 직접 답해도 된다.
  - 사무실에는 Claude·Codex 가 각각 캐릭터로 나타난다. 대화 기록은 탭을 닫으면 사라진다 (각 CLI 의 세션 기록은 남음).
- **코드 화면**: 사무실 위 「사무실 | 코드」 전환으로 왼쪽 영역을 읽기 전용 코드 보기(VS Code 와 같은 모나코 편집기)로 덮는다. 사무실은 그리기만 쉬고 계속 움직여, 돌아오면 캐릭터가 하던 일을 이어 하고 있다.
  - 폴더: 열린 탭의 작업 폴더(협업 대화 포함) 중에서 고르거나 「폴더 열기…」로 다른 폴더를 연다. 탭을 닫아도 앱을 끌 때까지 목록에서 고를 수 있다.
  - 왼쪽에 「이번 작업에서 건드린 파일」(에이전트가 고치거나 읽은 파일, ● 수정 · ○ 읽기)과 전체 파일 트리(깃 변경 표시 M·A·D·R·U), 오른쪽에 파일 내용. 바뀐 파일은 HEAD 와의 비교(변경 줄 강조)로 열린다.
  - 갱신: 코드 화면이 보일 때만 10초마다 `git status` 로 확인하고, 에이전트가 파일을 고치면 3초 뒤 한 번 앞당긴다. 조회는 `--no-optional-locks` 로 실행해 에이전트의 `git add`·`commit` 과 `index.lock` 을 다투지 않는다.
  - 깃 저장소에서만 동작한다 (아니면 안내만). 파일 목록은 20000개, 파일 내용은 2MB 까지, 바이너리는 표시하지 않는다.
  - 모나코는 번들러 없이 쓰려고 AMD 빌드(`monaco-editor@0.57.0` `min/vs`)를 버전 고정으로 쓰고, 코드 화면에서 처음 파일을 열 때 불러온다.
- **코드 분석**: 코드 화면의 「이번 변경 분석」(커밋하지 않은 변경 전체) 또는 「이 파일 분석」을 누르면 Claude 가 코드를 읽고 해설을 만든다. 누를 때만 실행되고 사용량이 든다.
  - 결과: 코드 줄 사이 주석(누르면 접힘, 「주석 표시」로 모두 끄기)과 하단 패널의 요약·읽는 순서·검색 키워드. 읽는 순서와 검색 결과를 누르면 그 줄로 이동한다. 실제 파일은 고치지 않는다. 하단 패널은 위쪽 경계를 끌어 높이를 바꾸고(편집기 120px 는 남김, 다음 실행에도 유지), 두 번 클릭하면 기본 높이로 돌아간다.
  - 모델: Sonnet(기본)·Opus·Fable 의 최신 버전, 노력 단계는 High 고정. 선택은 저장하지 않아 앱을 켜면 Sonnet 이다.
  - 결과는 앱이 켜져 있는 동안 메모리에만 있다. 변경 상태·내용과 모델이 그대로면 다시 실행하지 않고 이전 결과를 보여 준다(「다시 분석」으로 새로 실행, `git add` 만 해도 변경 상태가 바뀐 것으로 본다). 대상 20개 또는 변경 5만 자를 넘으면 실행 전에 확인한다. 실측 참고: 작은 변경 약 30초·$0.06, 24개 파일·5만 자 변경 약 100초·$0.47(Sonnet, API 환산 금액).
  - 주석은 모델이 준 줄 번호보다 그 줄의 코드 원문으로 위치를 찾는다. 분석 뒤 코드가 바뀌면 다시 찾거나(「위치 추정」) 숨기고 「분석 후 코드가 바뀜」을 표시한다.
  - 숨긴 `claude -p --restricted --safe-mode` 로 실행한다. 읽기 도구(`Read`·`Grep`·`Glob`)만 쓰고, 분석 폴더 밖은 읽지 못하며, 그 폴더의 설정·hook 을 적용하지 않는다. `.env`·키 파일(`*.pem`·`*.key`·`id_rsa*`)과 `.git` 안은 읽기를 막고, 이런 파일의 변경 내용도 프롬프트에 넣지 않는다(경로만 표시, 「이 파일 분석」은 거부). 사무실에 캐릭터로 나타나지 않고 세션 기록도 남기지 않는다.

## 그림 바꾸기

기본 화면은 아이소메트릭 **픽셀 오피스**다. Claude Code 캐릭터를 바탕으로 머리 6종과 안경·모자·리본·헤드셋 등 악세서리 7종을 등장 시 무작위 조합하고, 활동 중에는 외형을 유지한다.
중앙 사무실 8개 구역과 외곽 대표실·화장실이 고층 빌딩의 U자형 층을 구성한다. 짧은 연결 통로와 유리 난간, 아래층까지 이어지는 외벽으로 높이감을 표현한다. 문을 클릭하거나 가까이 가면 문이 열리고, 멀어지면 닫힌다.
분석실은 독서 책상 3개와 서재 소파, 기획실은 3인 협업 테이블 1개와 빈백, 팀장실은 L자 책상 1개와 원형 상담석이다. 개발실은 2인 벤치 2개, 검토실은 2인 리뷰 테이블 1개, 스킬실은 협업 작업대 2개를 사용하며 러그·서가·장비도 구역별로 다르다.
전체 보기(100%)에서는 사무실이 고정되며, 양옆 빈 공간 없이 가로를 채운다(세로 맞춤의 최대 116%). 세로가 넘치면 위쪽을 맞추고 아래로 이어지는 외벽 쪽만 잘린다. 사무실 칸이 세로로 길어 가로에 맞추면 위아래가 비는 경우에는 세로에 맞추고, 넘치는 양옆은 100% 에서도 드래그로 본다 — 칸이 다시 넓어지면 원래 맞춤으로 돌아간다. 상단 제목·날씨·확대 버튼은 한 줄로 두어 사무실 화면을 넓게 쓴다. 휠 또는 ＋/−로 100~400% 확대·축소하고, 확대된 화면만 가장자리 안에서 드래그로 살펴본다. 「전체 보기」는 화면을 맞추고 「내 캐릭터」는 내 위치를 보여 준다.
작업 중인 에이전트는 작업 지시와 최근 도구 호출을 짧게 정리한 말풍선을 지속해서 표시한다. 내용이 바뀐 직후에는 두 줄(작업 지시 + 지금 하는 일)로 보이고, 약 3초 뒤에는 한 줄 요약(「⌨ 코드 수정 중」 등)으로 줄어든다. 같은 종류의 도구를 계속 쓰면 한 줄 그대로이고, 종류가 바뀌거나 새 업무를 받으면 다시 두 줄로 펼쳐진다. 권한 확인은 우선 표시한다.
서울 시각 18:00~다음 날 07:00에는 창밖과 사무실 톤이 어두워지고 책상 스탠드가 켜진다. 조명은 감쇠·빛 번짐·접촉 그림자를 조합한 Canvas 연출이다.
도시 배경·배경 없음 테마는 서울 07:00~15:00에 낮, 15:00~18:00에 일몰, 18:00~다음 날 07:00에 일반 밤을 표시한다. 일몰에는 금빛 하늘·유리 반사와 창가의 따뜻한 햇살이 적용되며, 흐림·비·눈에는 빛이 약해진다. 22시 이후에도 일반 밤을 유지한다. 보랏빛 네온 야경은 시티팝 테마 전용이며, 커스터마이징에서는 낮·일몰·밤을 직접 선택하거나 자동 시간 전환을 사용하고 시티팝 조명을 별도로 선택할 수 있다.
주변 도시와 아래층 외벽은 최초 디자인 시안을 바탕으로 제작한 세밀한 배경 원화를 사용한다. 서로 다른 높이의 건물·강·다리·유리 반사를 살리고, 실제 픽셀 사무실의 바닥 좌표에 맞춰 합성한다. 후면 통창 4개에도 같은 풍경과 실내 조명의 옅은 반사가 이어진다. 낮·일몰·일반 밤의 원화를 전환하며 비·눈은 서울 날씨에 따라 움직인다. 먼 도시와 아래층 내부는 정적인 그림이고, 상부 사무실·캐릭터·상호작용은 실제로 동작한다. [Open-Meteo](https://open-meteo.com/)의 현재 날씨를 10분마다 조회하며, 조회 지연을 표시하고 관측이 한 시간 이상 오래되면 강수 연출을 멈춘다.
빈 바닥을 클릭하면 내 캐릭터가 가구를 피해 이동한다. 자판기·커피 바·노트북·소파를 클릭하면 다가가서 음료·작업·휴식 액션을 한다.
라운지 커피 머신에 도착하면 아메리카노·카페 라테·카푸치노·아이스 라테·레몬에이드·오렌지 소다를 작은 이미지와 이름의 스크롤 목록에서 선택한다. 목록과 손에 드는 음료는 같은 실사풍 PNG를 사용한다. 제조 후 컵을 45초 동안 들고 이동하며, 제조 중 다른 곳으로 이동하면 취소한다. 게임기 점수 연출·화분 물주기·책 읽기·스트레칭도 가구를 클릭해 이용한다. 게임 점수는 생활 연출용이며 앱을 켠 동안 최고 점수를 유지한다.
상주 캐릭터(모카·루프·코코, Codex 모습의 덱스)는 생활 연출이며 실제 Claude·Codex 에이전트 수에 포함하지 않는다. 작업을 마친 에이전트는 라운지에서 쉬다가 일이 생기면 돌아온다.
Claude의 `Skill` 호출이 수신되면 해당 캐릭터가 스킬 스튜디오로 이동한다. 방이나 캐릭터에 마우스를 올리면 호출된 스킬명을 볼 수 있다. 협업 연출(상주 캐릭터가 함께 모임)은 스킬을 새로 시작한 에이전트 수만큼 상주 최대 2명, 30초 동안만 한다.
스킬 전용 종료 이벤트는 사용하지 않으며, 호출명은 답변 완료(`Stop`)·새 요청·하위 에이전트 완료·세션 종료 시 정리한다.
상단 「테마」에서 「픽셀 오피스 · 도시 배경」과 「픽셀 오피스 · 배경 없음」을 선택한다. 배경 없음은 외부 도시와 아래층 외벽을 숨기고, 창밖은 초기 스타일의 단순 픽셀 건물과 하늘로 표시한다. 낮·밤과 비·눈, 실내 조명은 유지한다. 세 픽셀 테마의 왼쪽 벽은 대표실까지 이어지며, 중앙 출입구의 엘리베이터 문은 캐릭터 접근 시 열리고 멀어지면 닫힌다. 두 버전 사이를 전환해도 캐릭터 위치·음료·작업 상태·확대 배율을 유지하며, 선택은 다음 실행에도 기억한다. 화면 검증 결과는 `output/design/`에 저장된다.
세 번째 항목 「픽셀 오피스 · 시티팝 새벽」은 시간과 관계없이 보라·장밋빛 새벽 하늘, 초승달, 빌딩 숲과 먼 강변·다리를 표시한다. `cityscape.js`가 배경 전체를 픽셀 도형으로 직접 그린다. 가까운 빌딩은 사무실과 같은 사선과 픽셀 크기를 사용하고, 중경·원경으로 갈수록 크기·기울기·대비·창문 디테일을 줄여 원근을 표현한다. 실제 서울 시각·날씨 정보는 그대로 표시하고 비·눈만 실제 날씨에 따라 움직인다. 기존 두 픽셀 테마와 같은 사무실 상태를 공유한다.
이 테마의 사무실 건물은 외벽·창틀·블라인드·일부 켜진 조명·작은 실내 가구를 픽셀 도형으로 직접 그린다. 상부 사무실과 같은 반 픽셀 격자를 사용해 픽셀 크기를 통일하며, 건물 외벽에 이미지 원화를 사용하지 않는다.

## 알려진 한계

- 실행 중인 VS Code 세션 **안으로** 지시를 넣는 공식 방법은 없다 — 같은 폴더에서 새 세션을 열거나 복제해서 이어받는다.
- 결과 공유 연출은 시간 근접으로 추정한다 (메인 Claude 를 거치는 실제 흐름과 다를 수 있음).
- 협업 대화의 「자동」 모델 선택은 요청 문장의 단어로 고르는 단순 규칙이다. 필요하면 상단에서 직접 고른다.
- 협업 대화에서 AI 의 공식 질문 창(AskUserQuestion 등)은 화면 없는 실행에서 쓸 수 없어 `[질문]` 줄로 대신한다.
- Codex 가 답하는 중 보낸 메시지는 하던 작업(명령·파일 변경·MCP 도구·웹 검색·답변 글) 하나가 끝난 지점에서 지금 실행을 끊고 같은 세션으로 이어 답하게 한다 (Codex 실행 방식은 실행 중 입력을 받지 않음). 긴 명령 중에는 끝날 때까지 반영을 기다리고, 끊을 때 Codex 가 띄운 백그라운드 프로세스도 함께 끝날 수 있으며, 다시 실행하는 만큼 몇 초 늦고 사용량 패널의 요청 수가 늘어난다.
- 설치 파일은 코드 서명·앱 아이콘(기본 Electron 아이콘 사용)·자동 업데이트가 없다.
- 코드 화면의 「건드린 파일」은 hook 이 넘기는 경로로 모은다. Codex 가 한 번에 여러 파일을 고치는 패치는 첫 파일만 잡힌다 (나머지는 트리의 깃 변경 표시로 보인다). UTF-8 이 아닌 파일(예: CP949)은 글자가 깨져 보인다.
- 코드 분석은 분석할 코드를 평소 Claude 사용처럼 모델 서비스로 보낸다. 일반 소스 파일 안에 적힌 비밀값은 막지 못한다. 커밋한 뒤의 변경은 범위에 들어가지 않는다(「이 파일 분석」은 가능). `cmd` 경유로만 실행되는 옛 Claude Code 설치나 `--restricted` 가 없는 버전은 업데이트 안내만 한다.
